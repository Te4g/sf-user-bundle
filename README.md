# te4g/user-bundle

An opinionated Symfony 8.1 bundle for registration, email verification, password and magic-link login, password reset, profile and email changes, password changes, and guarded account deletion. The installer generates application-owned persistence, configuration, templates, components, assets, and one unexecuted Doctrine migration.

## Requirements

- PHP 8.4 or 8.5
- Symfony 8.1
- Composer 2 with Symfony Flex
- a Doctrine ORM database and a working Symfony Mailer transport
- an application route named `app_home`, unless the redirect configuration is changed

The installer owns the account firewall integration. The application's `main` firewall must not already define a provider, authenticator, pattern, stateless mode, or the other security keys reported by the install preflight.

## Install

The package and its contrib recipe must be published before these release commands work from Packagist. For local development, use `make smoke`, which exercises the same recipe through an isolated local Flex endpoint.

```bash
composer config extra.symfony.allow-contrib true
composer require te4g/user-bundle:^0.1

php bin/console te4g:user:install --dry-run
php bin/console te4g:user:install --no-interaction
```

Set the runtime environment before using the generated application:

```dotenv
APP_SECRET=replace-with-a-random-secret
DATABASE_URL="postgresql://app:password@127.0.0.1:5432/app?serverVersion=16&charset=utf8"
MAILER_DSN=smtp://127.0.0.1:1025
APP_URL=https://example.com
```

Use `APP_URL` as Symfony's `framework.router.default_uri` so links generated by workers and CLI processes are absolute:

```yaml
# config/packages/framework.yaml
framework:
    router:
        default_uri: '%env(APP_URL)%'
```

The installer creates exactly one migration but never runs it. Review the generated `migrations/Version*.php`, then execute it explicitly:

```bash
php bin/console doctrine:migrations:status
php bin/console doctrine:migrations:migrate
php bin/console te4g:user:install --no-interaction
```

Re-running the installer is a no-op while generated files still match its manifest. It stops on modified managed files instead of overwriting application work. The manifest is `config/te4g_user.install.json`.

## Routes

| Route | Path | Methods | Access |
| --- | --- | --- | --- |
| `te4g_user_register` | `/register` | GET, POST | public |
| `te4g_user_verify_email` | `/verify-email` | GET | public |
| `te4g_user_verify_resend` | `/verify-email/resend` | POST | public |
| `te4g_user_login` | `/login` | GET, POST | public |
| `te4g_user_login_link_request` | `/login-link` | POST | public |
| `te4g_user_logout` | `/logout` | POST | public |
| `te4g_user_login_link_check` | `/login-link/check` | GET, POST | public; completion is POST-only |
| `te4g_user_password_request` | `/forgot-password` | GET, POST | public |
| `te4g_user_password_reset` | `/reset-password/{token}` | GET, POST | public |
| `te4g_user_check_email` | `/check-email` | GET | public |
| `te4g_user_account` | `/account` | GET | fully authenticated |
| `te4g_user_profile` | `/account/profile` | GET, POST | fully authenticated |
| `te4g_user_email_change_confirm` | `/account/email-change` | GET | fully authenticated |
| `te4g_user_password_change` | `/account/password` | GET, POST | fully authenticated |
| `te4g_user_account_delete` | `/account/delete` | POST | fully authenticated |

Magic links trade password entry for control of an email inbox. Do not make inbox access the only factor for security-critical applications; add application-level step-up authentication or MFA.

## Development

Tests never download Tailwind. Download the Tailwind CSS 4.3.3 standalone binary yourself, verify the platform checksum in `tests/Fixtures/App/PinnedTailwindBinary.php`, and pass its absolute path:

```bash
export TE4G_TAILWIND_BINARY=/absolute/path/to/tailwindcss
make test
make smoke
```

`make test` runs coding style, PHPStan, PHPUnit, generated Twig/YAML checks, and the pinned asset/icon checks. `make audit` runs Composer's locked dependency audit. `make smoke` creates and removes only its own `mktemp` directory, installs a disposable Symfony application, leaves the generated migration unexecuted, and checks boot, routes, assets, icons, and representative HTTP responses.
